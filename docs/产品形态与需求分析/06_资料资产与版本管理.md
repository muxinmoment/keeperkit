# 资料资产与版本管理

## 资料类型

KeeperKit 未来可管理的资料，至少包括以下几类：

- 规则书
- 模组原文
- 用户笔记
- 跑团记录
- 玩家角色卡
- 图片资产
- 房规

其中，现阶段最值得优先管理的是：

- 规则书知识库
- 模组知识库
- 用户笔记
- 跑团记录
- 玩家角色卡

## 模组资料形态

用户常见的模组资料形态包括：

- PDF
- docs
- Markdown
- TXT
- 图片形式线索或附件

所以产品需要考虑的不只是“正文文本”，还包括附带图片、手牌、线索图等素材。

## 图片资产愿景

图片资产功能在长期愿景里是重要的，但第一阶段不一定直接生成图片。

更合理的路径是：

- 先能生成图片 prompt。
- 再逐步接入图片生成。
- 最后支持图片管理和绑定到 NPC、场景、手牌。

这样能先把工作流跑顺，而不是一开始就把视觉生成和资料管理同时做满。

## 版本管理原则

KeeperKit 必须支持“原始模组”和“我的改版模组”的版本关系。

最重要的原则有三个：

- 保留原始模组。
- 记录 AI 和手动改动。
- 不一改就覆盖全部内容。

这意味着系统更像版本管理器，而不是只会产出单个新文件的生成器。

## 资产管理原则

未来在资料资产层面，应尽量做到：

- 原始内容可追溯。
- 生成内容可区分。
- 修订内容可回滚。
- 个人笔记可单独检索。

这是 KeeperKit 从“查资料工具”走向“资料工作台”的关键一步。
