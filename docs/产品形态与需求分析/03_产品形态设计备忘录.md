# 产品形态设计备忘录

## 近期形态

KeeperKit 近期最合适的形态，是一个本地优先的 CoC 守秘人工具箱。

它应该能让用户：

- 导入模组。
- 选择一个当前模组。
- 看结构、问问题、查规则。
- 逐步整理出备团材料。

这个阶段最重要的不是“全部做完”，而是把最核心的工作流做顺。

## 中期形态

中期形态更接近围绕单个模组的备团工作台。

这意味着 KeeperKit 不再只是回答问题，而是开始支持：

- 模组结构视图
- 时间线整理
- NPC、地点、线索聚合
- 备团笔记
- 改写建议预览

这个阶段的产品会明显更像一个“跑团中枢”。

## 长期形态

长期形态是跑团中控台 + 复盘系统 + 模组改写闭环。

它至少应该支持：

- 跑团前：备团、读模组、整理线索。
- 跑团中：辅助查找、提示、润色、速查。
- 跑团后：复盘、修订、再创作。

如果未来图片、角色卡、记录和插件化都逐步接上，它就不只是一个问答工具，而是一个真正的跑团工作平台。

## 为什么不先做完整平台

完整平台的想象很美，但第一步如果铺得太大，容易把团队和产品都拖散。

当前更合理的路线是：

- 先做工具箱。
- 再把高频工具串成工作流。
- 最后才考虑做完整平台。

这种方式更贴近实际使用，也更容易持续迭代。

## 主界面方向

长期愿景里，主界面更适合做成“跑团中控台”风格，而不是纯聊天窗口。

原因是跑团不是一句一句聊天就能完成的事情，它需要：

- 结构化浏览。
- 来源对照。
- 任务区。
- 现场辅助。
- 版本追踪。

所以 KeeperKit 的界面应该始终有工具感，而不是只剩对话感。
