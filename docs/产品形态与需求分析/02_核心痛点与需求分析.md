# 核心痛点与需求分析

## 主要痛点

KeeperKit 需要解决的不是单点问题，而是一整串跑团高门槛问题：

- 规则难查，且查到之后还要确认依据。
- 模组信息分散，难以快速掌握结构。
- 备团很累，尤其是时间线、NPC、线索和场景关系整理。
- 有些模组不符合预期，但改起来成本高。
- 跑团中临场描述、补细节和记忆压力大。
- 跑团后缺少复盘工具，经验难沉淀。

## 需求分层

### 分析整理类需求

这类需求是当前最优先的方向：

- 时间线整理
- 线索聚合
- NPC 动机分析
- 场景索引
- 模组结构视图
- 规则与模组依据引用

这类能力的重点不是“生成很多新内容”，而是把已有内容理清楚。

### 创作生成类需求

这类需求更偏向后续增强：

- 补充场景细节
- 改写剧情
- 生成新 NPC
- 生成道具文本
- 生成图片 prompt

创作生成不是不要，而是需要严格区分来源和建议，不能把 AI 生成内容伪装成原文。

## 来源边界

KeeperKit 需要始终区分三种东西：

- 规则书依据
- 模组原文依据
- AI 新增建议

这是产品能否可信的关键。

在备团模式下，关键结论尽量都要能追溯来源。

在跑团中，可以允许更灵活的描写和润色，但关键道具、关键线索、关键结论必须标注来源或明确标出是新增建议。

## 改写边界

模组修改不是“AI 代替守秘人改完一切”，而是：

- KP 提出目标和方向。
- AI 给出可选改法、补丁或改写建议。
- KP 决定是否采用。
- 系统保留原文和修订版的对照。

这能避免两个很危险的事情：

- 把 AI 生成内容误当成原模组内容。
- 把房规或临时改动伪装成 CoC 规则。

## 当前最重要的需求结论

从产品优先级看，当前最值得先做的是：

- 模组导入
- 模组结构化
- 模组问答
- 时间线整理
- 版本管理

这些是整个跑团工具链里最基础、也最容易验证价值的部分。
