# 信息架构与界面形态

## 主要工作区

KeeperKit 的信息架构建议围绕以下几个工作区展开：

- 规则问答
- 模组库
- 模组结构视图
- 备团助手
- 改写助手
- 跑团现场模式
- 跑团记录与复盘

这些区域不是孤立页面，而是围绕同一个模组和同一个工作流展开。

## 推荐布局

界面更适合采用三栏式工作台：

- 左侧：模组与功能导航
- 中间：任务工作区
- 右侧：sources、笔记、风险提示、AI 建议

这个布局的好处是，用户可以一边看结构，一边看生成结果，一边核对来源。

## 必须支持的模组结构视图

模组结构视图是这个产品的核心之一。

建议自动分栏的内容包括：

- 场景
- NPC
- 地点
- 线索
- 手牌
- 怪物
- 结局
- 时间线

这类结构能帮助守秘人从“散文式阅读”切换成“工作流式阅读”。

## 跑团现场模式

现场模式是长期愿景，但应在架构上保留入口。

现场模式中，界面应尽量只显示当前需要的东西，例如：

- 当前场景
- 可透露线索
- NPC 快速卡
- 规则速查
- 玩家状态
- 隐藏守秘人信息

这样 KeeperKit 才真的像一个跑团中控台。

## 视图切换逻辑

不同任务对应不同视图：

- 查规则时，重点是问答和来源。
- 备团时，重点是结构、时间线和改写建议。
- 跑团中，重点是现场模式和速查。
- 跑团后，重点是复盘和修订。

这比单纯把所有功能塞进一个聊天窗口更符合真实工作方式。
