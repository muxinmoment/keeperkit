# RAG Step 09：黑话检索改写与弱依据回答策略

## 本步目标

优化两个体验问题：

```text
1. 用户问“车卡”“撕卡”“SC”等玩家黑话时，规则书里可能没有这些词，导致检索失败。
2. 用户问规则书没有直接写的内容时，系统过于僵硬，只回答“没有依据”。
```

本步不改索引结构，只在查询和回答阶段做轻量增强。

## 修改内容

新增查询改写模块：

```text
backend/app/rag/query_rewriter.py
```

它会把常见黑话补充成规则书更容易命中的检索词。例如：

```text
车卡 -> 创建调查员、角色创建、调查员创建、属性、技能、职业、背景
SC/SAN -> 理智检定、理智损失、理智值
DB -> 伤害加值、体格、力量、体型
```

服务层改为：

```text
原始问题保留给 LLM 回答
改写后的 retrieval_question 用于 embedding 检索和 rerank
query_notes 传给 prompt，提示 LLM 这是黑话扩展，不是规则原文
```

更新文件：

```text
backend/app/services/rule_qa_service.py
backend/app/rag/prompts.py
backend/app/rag/generator.py
```

新增测试：

```text
backend/tests/test_query_rewriter.py
```

## 回答策略变化

旧策略：

```text
没有足够依据时，只回答“当前规则资料中未检索到明确依据。”
```

新策略：

```text
1. 规则、数值、流程仍然必须基于检索片段。
2. 没有足够依据时，先说明没有明确规则书依据。
3. 可以给出通用建议或提问引导，但必须标明不是规则书依据。
4. 可以解释 TRPG/CoC 常见黑话，但不能把黑话解释伪装成规则原文。
```

## 示例

用户问题：

```text
新手怎么车卡？
```

检索问题会扩展为：

```text
新手怎么车卡？
检索补充词：创建调查员、角色创建、调查员创建、属性、技能、职业、背景
```

这样更容易召回：

```text
第三章 创建调查员
技能列表
职业与背景
```

LLM 回答时仍然看到用户原始问题，并会知道“车卡”是黑话扩展。

## 后续可优化

1. 把黑话表迁移到 JSON/YAML，方便非代码维护。
2. 给前端展示“已按哪些术语扩展检索”。
3. 为弱依据回答增加结构化字段，例如 `answer_mode=grounded|mixed|fallback`。
4. 针对“剧情建议/房规/带团建议”单独做非规则书知识模式开关。
