# KeeperKit 现阶段开发与交接总结

这份文档用于把 KeeperKit 当前已经做到哪一步、现在怎么跑、下一轮该从哪里继续，集中记清楚。  
它不是新 PRD，只是一份给后续开发直接接手用的状态说明。

## 1. 当前项目状态

KeeperKit 现在已经从“规则书问答工具”走到了“模组助手 + 备团工作台”的阶段。

当前主线已经完成三层能力：

1. 规则书 RAG 问答
2. 模组结构识别与材料浏览
3. 备团助手的全文整理、结构化展示和会话记忆

目前前端主工作台已经分成四个标签页：

- `模组问答`
- `备团助手`
- `结构视图`
- `来源依据`

## 2. 已完成的版本内容

### V1.0：模组助手基础版

这一版把模组作为独立对象接进来，完成了最基础的模组工作流：

- 模组创建、列表、删除
- 上传模组资料
- 建立索引
- 基于模组做问答
- 让前端真正进入“模组工作台”而不是单纯规则问答页

### V1.1：模组结构视图

这一版把“看资料”从纯文本浏览推进到了结构化索引视图：

- 模组资料分组浏览
- 场景、NPC、线索、地点等结构信息可视化
- 为后续备团整理提供材料底座

### V1.2：备团助手基础版

这一版是当前最核心的阶段，重点是“帮守秘人备团”：

- PDF 正文识别
- 备团助手标签页
- 全文备团生成
- 本地对话保存
- LangGraph 备团草稿
- PostgreSQL 会话记忆
- 结构化 JSON 备团输出
- 时间线思维导图式展示
- NPC / 线索卡片展示
- 备团结构工作流展示
- 单块内容可编辑、可 AI 重整

## 3. 现在的产品形态

当前 KeeperKit 的实际形态已经比较明确了：

- 先以模组为核心单元
- 先解决新人守秘人的备团问题
- 先做“分析整理”
- 再逐步扩展到“改写、复盘、现场辅助”

现在的备团助手不是一段长文本提纲，而是一套结构化工作台：

- `overview`：备团总览
- `must_know`：跑团前必须知道
- `timeline`：时间线
- `workflow`：备团结构地图
- `npcs`：NPC 卡片
- `clues`：重要线索卡片
- `locations`：地点与手牌
- `risks`：可能卡住的地方
- `checklist`：跑团前检查清单

## 4. 目前技术链路

### 后端

- 框架：FastAPI
- 备团草稿：LangGraph
- 会话记忆：PostgreSQL checkpointer
- 全文备团：直接读取模组全文资料
- 数据输出：AI 直接返回 JSON，后端解析后落成结构化模型

### 前端

- 框架：React + Vite
- 主界面：标签页式工作台
- 备团展示：结构化卡片、工作流、时间线导图
- 编辑方式：区块级 AI 重整 + JSON 草稿编辑

### 数据形态

- 模组原文：`documents/`
- 处理中间产物：`processed/`
- 对话与备团草稿：本地持久化
- 会话记忆：PostgreSQL

## 7. 当前设计取向

KeeperKit 现在的方向不是“把所有东西都做成文本”，而是：

- AI 先输出结构化数据
- 前端按结构展示
- 用户再对结构块逐段修改
- AI 在同一模组会话里继续修订

也就是说，现在的核心不是“再生成一段长文”，而是“让模组资料能被看、能被改、能继续推演”。

## 8. 后续最自然的开发方向

下一步比较适合继续做这些：

1. 把时间线和工作流做成更强的交互式图谱
2. 给 NPC、线索、地点增加更细的字段编辑器
3. 增强“AI 重整”时的局部重写能力
4. 把跑团记录、复盘、现场辅助继续接上
5. 后面再扩展图片资产、手牌、模组改写闭环

## 9. 交接时要记住的点

- 现在的主工作方向已经不是规则书问答，而是模组备团
- 备团数据的主展示应该优先结构化，不要退回长文本
- AI 生成结果要尽量保持 JSON 可解析
- 同一个模组要尽量复用同一条会话线程和本地草稿
- 后续如果继续扩展，优先围绕“结构化、可编辑、可重整”这三个词推进
